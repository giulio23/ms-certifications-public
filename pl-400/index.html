Common Exam Traps

Distinctions PL-400 loves to test

Where does the business logic go?

Real-time, transactional, must-always-run → a synchronous plug-in. Cross-system/async automation → a cloud flow. Simple form-field logic no-code → a business rule. UX-only validation → client script. Match the requirement to the extension point.

Plug-in pipeline stages

Pre-validation runs outside the transaction (before security); Pre-operation and Post-operation run inside it. Use PreImage to read prior values, PostImage for the saved result. Register sync for immediate needs, async to offload work.

Web API vs Organization service

The Web API is RESTful/OData v4 — use it from JavaScript, external apps, and anything HTTP. The Organization service (IOrganizationService) is the .NET SDK used inside plug-ins/custom code. Same data, different entry point.

Plug-in vs webhook/Service Bus

In-process business logic → a plug-in. To notify an external system, publish the event to a webhook, Azure Service Bus, or Event Hub via a service endpoint (registered with the Plug-in Registration Tool). That is D6 territory, not D5.

PCF vs client scripting

Client scripting (JavaScript + Client API) reacts to form events and calls the Web API. A PCF code component is a reusable, packaged UI control (manifest + lifecycle) bound to a field or dataset. Reach for PCF when you need custom UI, not just event logic.

Sync: change tracking & Upsert

Enable change tracking to sync only deltas to an external store. Use alternate keys so external ids map to Dataverse rows, and UpsertRequest to insert-or-update in one call — the standard pattern for integration/data sync.
